# Consolidate Alembic Files Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the 15 migration files under `backend/alembic/versions/` with a single autogenerated migration matching current `app/models/`, since #2211 confirms the DB will be dropped in prod/stage/dev — no upgrade path needs to survive the collapse.

**Architecture:** Same mechanism as the last collapse (commit `72d56d58`, 2026-06-15): delete every file in `alembic/versions/`, run `make db-revision` against a fresh empty DB to autogenerate one `create_all`-shaped migration. Two partial unique indexes found during planning (`uq_active_datasource_per_module`, `uq_carbon_projects_unit_type_nonplan`/`_unit_plan_name`) existed only in migration history, not in model code — rather than hand-writing them into the new migration, Task 0 moves them into `__table_args__` (mirroring the existing pattern in `factor.py`/`data_ingestion.py`/`data_entry.py`) so `alembic revision --autogenerate` emits them itself. The only thing left to hand-restore in the migration is the `pg_trgm` extension, which is a `CREATE EXTENSION` statement with nothing in SQLAlchemy to hang it off. `backend/alembic/CUSTOM_DB_OBJECTS.md` is the existing source of truth for these items — this plan updates it rather than re-deriving it.

**Tech Stack:** Alembic, SQLModel/SQLAlchemy, Postgres 16, `uv run` (backend), pytest.

**Spec:** GitHub issue [#2211](https://github.com/EPFL-ENAC/co2-calculator/issues/2211) — "Merge all alembic files, to drop data migrations. We'll drop database."

## Global Constraints

- Never hand-author Alembic migrations — generate via `make db-revision`, then prune false-positive `drop_index` calls (guardrails.md).
- The pruning target this time is the opposite direction: autogenerate normally _adds_ false-positive drops for existing partial indexes; check for the same class of noise (expression/partial indexes, `postgresql_where`) in the fresh diff.
- No silent data loss disguised as cleanup: every item in `CUSTOM_DB_OBJECTS.md`'s "Active" and "Captured in models" sections must be verified present in the new migration before merging.
- `make ci` (ruff + ty + vue-tsc) must pass; this PR only touches `backend/`.

  - `uq_active_datasource_per_module` on `connector_datasources` (from `89c3079e388d`): unique on `(module_type_id, COALESCE(data_entry_type_id, 0))` where `is_active = true`. `app/models/connector.py`'s `ConnectorDatasource` had **no `__table_args__` at all** — not even a comment noting the index existed in the DB only.

No hand-authored index DDL in the migration; only `pg_trgm` needs that treatment (see Task 1, Step 3).

It does not need to survive into the squashed migration — the collapsed migration runs once against an empty DB, where a plain `CREATE UNIQUE INDEX` is instant. - [x] **Step 1: Add the import and index to `ConnectorDatasource`**

`app/models/connector.py` — add `Index, text` to the `sqlalchemy` import, then on `ConnectorDatasource`:

```python
__table_args__ = (
    # One active datasource per module target. Postgres treats each NULL
    # as distinct, so the raw column can't be indexed directly — coalesce
    # it into the expression instead. ddl_if gates to Postgres: SQLite
    # drops the partial WHERE, turning this into an unconditional unique
    # and breaking tests that legitimately reuse (module_type_id, None).
    Index(
        "uq_active_datasource_per_module",
        "module_type_id",
        text("COALESCE(data_entry_type_id, 0)"),
        unique=True,
        postgresql_where=text("is_active = true"),
    ).ddl_if(dialect="postgresql"),
)
```

- [x] **Step 2: Add the import and indexes to `CarbonProject`**

`app/models/carbon_project.py` — add `Index, text` to the `sqlalchemy` import, then replace the comment-only block on `CarbonProject` with:

```python
__table_args__ = (
    # Two partial unique indexes. ddl_if gates both to Postgres: the
    # SQLite unit-test schema is intentionally unconstrained here.
    # One project per (unit_id, carbon_report_type) for Calculator /
    # Simulator_Explore; a unit may hold multiple Simulator_Plan
    # projects instead, unique per (unit_id, name) since the name is a
    # URL identifier.
    Index(
        "uq_carbon_projects_unit_type_nonplan",
        "unit_id",
        "carbon_report_type",
        unique=True,
        postgresql_where=text("carbon_report_type != 'Simulator_Plan'"),
    ).ddl_if(dialect="postgresql"),
    Index(
        "uq_carbon_projects_unit_plan_name",
        "unit_id",
        "name",
        unique=True,
        postgresql_where=text("carbon_report_type = 'Simulator_Plan'"),
    ).ddl_if(dialect="postgresql"),
)
```
